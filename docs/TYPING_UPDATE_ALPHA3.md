# 타이핑 붙여쓰기 수정 — 2.0.0-alpha.3

## 적용 범위

버전 1과 버전 2 실행용 앱의 기존 ‘⌨ 타이핑으로 넣기’에 적용한다.
버전 2의 독립 `/preview/`는 기존 시안 그대로이며 이 실제 입력 기능과 혼동하지 않는다.
이 묶음은 앞서 제공한 alpha.2의 전체 업로드 묶음을 대체한다.

- `도도솔솔`과 `도 도 솔 솔`은 동일하게 도·도·솔·솔 네 음을 **순서대로** 만든다.
- `도도솔솔라라솔-파파미미레레도-`도 입력할 수 있다.
- `도#레♭쉼미/파-솔5라^시v`처럼 반음·쉼표·음 길이·옥타브 기호도 유지한다.
- 한 음의 기준 길이, 넣을 위치, 왼손으로 표시, 기존 트랙 끝 추가, 되돌리기·저장 호출은 원본을 유지한다.
- `도미솔`은 세 음의 순차 입력이다. 동시에 치는 화음 입력 기능을 새로 만든 것은 아니다.
- 영어는 기존처럼 `c c g g`로 띄어 쓴다. 기존 `ab`는 A-flat(라♭)으로 유지한다.
- 읽을 수 없는 글자를 버리고 나머지만 악보에 넣지 않는다. 오타가 섞이면 원래 ‘읽을 수 없는 글자’ 오류 경로에서 삽입 전체를 중단한다.
- IME/키보드 입력을 가로채지 않는다. 완성된 문자열을 기존 ‘넣기’ 버튼으로 처리한다.
- 입력 안내와 ‘한 글자 길이’ 라벨을 ‘한 음 길이’로 수정한다.

## 원본 보존과 배포

원본 `parseNoteText`의 토큰 분리 부분과 안내 문구 두 곳만 명시적으로 수정한다.
음높이·길이 계산, 실제 삽입 핸들러, 손 지정, AI·녹음·메트로놈·파일 기능의 코드는 이번에 바꾸지 않는다.
각 빌더의 역변환 검사에는 새 타이핑 수정도 포함한다. 원본 앵커가 변경되면 추측해서 적용하지 않고 빌드를 중단한다.
버전 1의 저장소 원본 index.html은 변경하지 않고 Actions의 배포 사본에 적용한다.
버전 2는 기존과 같은 고정 원본 커밋에서 빌드하면서 이번 패치를 적용한다.
서비스 워커 빌드 식별자는 변경된 HTML/버전에 의해 새로 계산된다. DB/설정 이름 공간은 이번에 바꾸지 않는다.

업로드 폴더는 기존과 같다.

| 폴더의 내용물 | 저장소 |
|---|---|
| UPLOAD_TO_piano-studio-next | piano-studio-next |
| UPLOAD_TO_piano-studio | piano-studio |

이미 alpha.2를 올렸으면 같은 경로의 파일을 덮어쓰고 새 파일도 추가한다. 원래 앱 파일/폴더를 삭제하지 않는다.
아직 올리지 않았다면 이번 ZIP만 사용한다. 새로 추가된 typed_note_patch.py와 검사 파일을 빠뜨리지 않도록 각 폴더의 내용물을 전부 업로드한다.
Pages의 GitHub Actions 설정은 기존과 같다. 앱에서 ‘붙여 쓰거나 띄어 써도’ 안내가 표시되면 이 입력 패치가 적용된 화면이다.

- 버전 2 빌드·소스 보존·타이핑 단위검사: 24/24 통과.
- 버전 1 빌드·소스 보존·타이핑 단위검사: 14/14 통과.
- 실제 원본 파서 발췌 대비 비교/검증: 9,433개 통과. 기존 음 기호 조합과 1,000개 결정적 무작위 붙여쓰기 수열 포함. 같은 검사 세트를 두 빌더에서 실행한 것이므로 서로 다른 18,866개의 입력 사례로 세지 않는다.
- Chromium에서 실제 원본 타이핑 창/삽입 핸들러를 합성 앱 상태·보조 함수에 연결: 버전 1/2 × 화면 크기 3개, 총 36개 검사 통과. 반복음 순차 삽입, 왼손·옥타브, 길이·쉼, 재생 위치, 잘못된 입력 시 삽입 안 함, 취소를 확인.
- 버전 1/2 서비스 워커 모의검사: 각각 17/17 통과. 실제 Safari/PWA 검사 아님.

공개 원본은 웹으로 확인하고 타이핑 부분을 발췌해 검사했다. 원본 전체 저장소를 이 환경에 내려받아 실행하거나 사용자 계정에서 실제 배포한 것은 아니다.
아이폰/iPad 실기기 Safari, 실제 녹음·AI·악보 렌더러 전체 연결은 이 검사의 범위가 아니다.
별도 UI 시안과 원본 엔진의 완전한 통합, 인식률·자동 양손 분리·편곡 개선을 완료한 버전도 아니다.
